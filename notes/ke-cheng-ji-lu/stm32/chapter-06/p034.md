## 中断优先级的概念

在正式讲解中断优先级之前，我们先用看门诊的情形作个类比。请先把自己想象成一名正在门诊看病的大夫。病人一到来时，大夫停止休息，开始给病人一看病。看诊过程中，病人二和病人三又来了。病人二是普通病人；病人三比较着急，因为他赶火车。大夫先把病人一看完，再优先给比较急的病人三看病，最后才看病人二。虽然病人二先到，病人三的事情更急，所以处理顺序是先病人三、再病人二。

![两组门诊示意图：普通病人与较紧急病人先后到来，用来说明事件的轻重缓急。](<../../../.gitbook/assets/f001 (26).jpg>)

_两组门诊示意图：普通病人与较紧急病人先后到来，用来说明事件的轻重缓急。 ·_ [_原片 01:07_](https://www.bilibili.com/video/BV11X4y1j7si/?p=34\&t=67)

我们再看第二个例子：大夫仍在门诊，病人四到来，大夫开始给他看病。这时来了病人五，他的病情非常危重，属于急诊。病人五到来后，大夫打断给病人四看病的过程，优先处理病人五；急诊处理完，再回来继续给病人四看病。

这两个例子说明，即使都是突发事件，事情之间也有轻重缓急。第一个例子里，病人二虽然先到，病人三更急，所以先看病人三；第二个例子里，正在处理病人四时来了急诊，大夫必须停下手头的看诊，转去处理病人五，再回来继续病人四。处理突发事件时，要优先处理重要且紧急的事情。中断优先级就是用数字表示中断紧急程度的一种方式。

## 片上外设怎样产生中断

我们先回顾片上外设的概念：片上外设就是芯片内部的一个个模块，它们像身体上的不同器官，各自负责执行独立的功能。之前学过的 GPIO、USART、I²C、SPI 等模块都属于片上外设。本章学习的中断，就是由芯片上的这些片上外设产生的。

比如串口模块 USART 可以产生一路中断。看 USART 的内部结构框图，它只能产生一个中断，也就是右侧标出的 USART 全局中断。框图里还有许多粉红色的 0 和 1，它们代表 USART 的标志位，标志位的值反映 USART 当前的工作状态。

例如之前学过的 RXNE 标志位，表示接收数据寄存器非空。当它的值从 0 变成 1，就表示接收数据寄存器里已经有数据。此时可以通过 RXNE 标志位触发中断，再把数据处理代码写在中断响应函数里。这样就能及时处理接收到的数据。

除了 USART 串口模块，其他模块也可以产生中断。I²C 模块可以产生两路中断：一路叫 I²C 错误中断，另一路叫 I²C 事件中断。SPI 模块可以产生一路中断，就是 SPI 全局中断。之后学习的 EXTI 模块可以产生多路中断：EXTI0、EXTI1、EXTI2、EXTI3、EXTI4、EXTI9\_5，以及 EXTI15\_10，等等。

## NVIC 管理中断并调用响应函数

除了刚才这些模块，还有很多其他模块也能产生中断。我们使用的单片机有很多片上外设，几乎每一个片上外设都能产生一个或多个中断，所以中断的数量会非常多。中断一多，就需要管理，因此请来了一个管理员，叫 NVIC。NVIC 专门管理这些中断，它会根据每一路中断的优先级给中断排队，排在前面的中断优先得到响应。

CPU 响应中断时，需要调用这个中断的中断响应函数。那么 CPU 到哪里找响应函数呢？它从最右边的中断向量表里找。中断向量表把每一种中断对应的中断响应函数逐个列在里面。中断触发后，CPU 根据向量表找到相应的响应函数并执行；响应函数执行完成，这次中断也就处理完了。这就是中断处理的流程。

刚才说 NVIC 是中断管理员，所以每一路中断的优先级就存储在 NVIC 里面。把框图里的 NVIC 区域放大后可以看到，每一路中断对应四个小方格，这四个小方格就是四个比特位。每一位可以填 0 或 1，通过填写不同的 0 和 1 得到不同的优先级。四个小方格中间有一条竖线，表示中断优先级的分组；旁边的左右箭头表示可以移动这条线。

## 四位优先级与分组

![NVIC 每路中断的优先级由四个比特位表示，分组线把抢占优先级与子优先级分开。](<../../../.gitbook/assets/f003 (26).jpg>)

_NVIC 每路中断的优先级由四个比特位表示，分组线把抢占优先级与子优先级分开。 ·_ [_原片 07:30_](https://www.bilibili.com/video/BV11X4y1j7si/?p=34\&t=450)

中断优先级分组共有五种：分组 0、1、2、3、4。分组 0 把四位全部分给子优先级；分组 1 留一位给抢占优先级、三位给子优先级；分组 2 是两位抢占、两位子优先级；分组 3 是三位抢占、一位子优先级；分组 4 则把四位全部分给抢占优先级。

以四位二进制数 1011 为例，分组方式会改变抢占优先级和子优先级的数值。分组 0 下，抢占优先级没有可用位，可简单看作 0；子优先级是 1011₂，即 8+2+1=11。分组 1 下，最高位 1 属于抢占优先级，后三位 011 属于子优先级，因此是抢占优先级 1、子优先级 3。

分组 2 下，前两位 10₂ 是抢占优先级 2，后两位 11₂ 是子优先级 3。分组 3 下，前三位 101₂ 是抢占优先级 5，最后一位 1 是子优先级 1。分组 4 下，四位 1011₂ 全部属于抢占优先级，即 11；子优先级没有分到位，按 0 处理。

## 抢占优先级与中断嵌套

因此，在 STM32 中，每路中断的优先级用四个比特位表示，再由分组线划成抢占优先级和子优先级。接下来我们来看抢占优先级与中断嵌套的关系。中断嵌套是指当前正在执行的中断被一个更高优先级的中断打断，转而处理新中断，完成后再回来继续原来的中断。就像给普通病人看病时来了急诊，普通看诊被打断，急诊处理完成后再继续。

中断嵌套发生的条件是：新中断的抢占优先级高于正在执行中断的抢占优先级。下面使用分组 2，也就是两位抢占优先级、两位子优先级，来看四路中断。

![分组二将四位拆为两位抢占优先级和两位子优先级；示例列出四路中断的编码。](<../../../.gitbook/assets/f004 (26).jpg>)

_分组二将四位拆为两位抢占优先级和两位子优先级；示例列出四路中断的编码。 ·_ [_原片 12:30_](https://www.bilibili.com/video/BV11X4y1j7si/?p=34\&t=750)

四位编码分别是中断一 1001、中断二 1000、中断三 0011、中断四 1110。按两位一组拆分后，中断一的抢占优先级为 10₂=2、子优先级为 01₂=1；中断二是抢占优先级 2、子优先级 0；中断三是抢占优先级 0、子优先级 3；中断四是抢占优先级 3、子优先级 2。

先看最左边的时序图：一开始执行的是常规程序，发生中断一后，常规程序被打断，转而执行中断一的中断响应函数。在中断一的响应函数执行过程中，又发生中断二。现在看中断二会不会对中断一形成嵌套：中断二的抢占优先级是 2，和中断一的抢占优先级相等，也是 2。它并不比中断一的抢占优先级更高，所以不会发生中断嵌套。处理顺序是先执行完中断一的响应函数，再执行中断二的响应函数，最后才回到常规程序。

再看中间的时序图。一开始同样执行常规程序，发生中断一后转去执行中断一的响应函数；在此期间又发生中断三。中断三的抢占优先级是 0，中断一的抢占优先级是 2。这里要记住：对于中断优先级，数字越小，优先级越高。因此中断三的 0 比中断一的 2 高，中断三会对中断一形成嵌套。中断一的响应函数被打断，转去执行中断三的响应函数；中断三执行完成后，再继续处理被打断的中断一，完成后回到常规程序。

最后看右边的时序图：还是在执行中断一的响应函数时发生了中断四。中断四的抢占优先级是 3，中断一的抢占优先级是 2。由于数字越小表示优先级越高，这里中断一的优先级更高，中断四不能对中断一形成嵌套。处理顺序是先执行完中断一的响应函数，再执行中断四的响应函数，然后回到常规程序。

第三部分到这里结束。我们已经了解中断嵌套，以及抢占优先级和嵌套的关系。下面进入第四部分，学习子优先级和中断排队的关系。

## 子优先级与中断排队

为了说清楚中断排队，我们再来看高铁检票的例子。大家应该都坐过高铁，坐车之前要检票；检票时几个相应班次会一起检。所谓中断排队，就是几个中断的优先级相仿时，等待前一个中断执行完成，再去处理新的中断。检票员原本在休息，乘客一来了，检票员就开始给乘客一检票；检票过程中又来了乘客二、三、四、五。因为这四位乘客的优先级跟乘客一差不多，所以先把乘客一的检票过程做完，再给后面的乘客检票。

![乘客按发车时间排队：乘客四、三、五、二依次检票，先到的同优先级乘客排在前面。](<../../../.gitbook/assets/f005 (25).jpg>)

_乘客按发车时间排队：乘客四、三、五、二依次检票，先到的同优先级乘客排在前面。 ·_ [_原片 15:30_](https://www.bilibili.com/video/BV11X4y1j7si/?p=34\&t=930)

这些乘客的优先级仍有区别，可以按发车时间排队：乘客二乘坐 8:00 的车；乘客三和乘客五乘坐 7:55 的车；乘客四乘坐 7:50 的车。因此完成乘客一后，先给最早发车的乘客四检票；乘客三和五都在 7:55 发车，乘客三先到，就排在乘客五前面；最后给 8:00 发车的乘客二检票。顺序是 1、4、3、5、2。检完后检票员再次休息。

单片机中断排队也遵循三个原则。第一，新中断的抢占优先级不高于当前中断时，不会形成嵌套。第二，多个待处理的中断中，优先级更高的排在前面。第三，两个中断优先级相同时，按先来后到排队。

## 练习题

前面的概念讲完了，下面进入第五部分练习题。假定使用分组 2，即两位抢占优先级加两位子优先级。一开始执行常规程序，中断一到来，假设它的抢占优先级是 2、子优先级是 3。因为当前执行的是常规程序，中断一会打断常规程序，转去执行中断一的响应函数。 ![练习题波形总结：中断五抢占执行中的中断二，其余中断依子优先级和到达顺序排队。](<../../../.gitbook/assets/f006 (24).jpg>)

_练习题波形总结：中断五抢占执行中的中断二，其余中断依子优先级和到达顺序排队。 ·_ [_原片 19:30_](https://www.bilibili.com/video/BV11X4y1j7si/?p=34\&t=1170)

中断一的中断响应函数正在执行时，中断二又发生了。先看中断二会不会对中断一形成嵌套：它们的抢占优先级都是 2，所以不会嵌套。等中断一的响应函数执行完成，才执行中断二的响应函数。

中断二的响应函数执行过程中，又发生中断 3、4、5、6。我们还是先判断中断 3、4、5、6 会不会对中断二形成嵌套。中断二的抢占优先级是 2，中断 3、4、6 的抢占优先级不比它高，所以这三路不会形成中断嵌套；中断 5 的抢占优先级是 1，数值更小、优先级更高，因此中断 5 会形成嵌套。此时必须中断中断二，转而执行中断五的中断响应函数。

除了中断五以外，中断三、中断四和中断六都不会形成嵌套，所以需要排队。中断三的抢占优先级是 3，写成二进制是 11；子优先级也是 3，也写成 11。因此它的四位总优先级是 1111₂，也就是十进制 15。中断四的总优先级是 14，中断六的总优先级也是 14，所以中断四和中断六的优先级更高，排在中断三前面。又因为中断四先发生，按先来后到，先处理中断四，再处理中断六，最后处理总优先级最低的中断三。

处理完等待队列后，程序回到常规程序；这就是练习题的完整波形。最后我们回顾一下：中断优先级的概念；STM32 用四位二进制数表示每路中断的优先级，并把它分成左侧的抢占优先级和右侧的子优先级；抢占优先级关系到中断嵌套，子优先级关系到中断排队。感谢大家收看，我是铁头山羊，让我们下期视频再见。
